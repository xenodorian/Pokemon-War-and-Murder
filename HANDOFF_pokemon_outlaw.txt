1. WHAT THIS PROJECT IS
=====================================================================
The user plays "Pokemon Outlaw" (a FireRed 1.0 / BPRE hack, build outlaw-2015-09-05) on an R36S handheld
(RetroArch, mGBA core). I make patches on top of that ROM using one Python build script. The user wants:
  - a single already-patched .gba
  - a matching RetroArch save state (.state) whose ROM CRC is re-paired to the new ROM
  - optionally the IPS patch (against the original ROM)
Each delivery gets a name like "Pokemon Outlaw Quest Log (Slimosaur).gba" / ".state".
Everything is verified in an emulator harness only, never on real hardware. Say so in deliveries.

The user will NOT have the original ROM in a new chat unless they re-attach it. Ask them to attach
f4046af2-outlaw-2015-09-05.gba (the unpatched hack ROM, 16,777,240 bytes) and their latest .state.

4. HOW TO BUILD AND DELIVER A RELEASE
=====================================================================
1. cd /home/claude/work && env -u DEBUGWARP -u DEBUGCANDY -u DEBUGTRAINER -u DEBUGMUT -u DEBUGMART \
     -u DEBUGBATTLE python3 -I tools/build.py "/home/claude/work/out/Pokemon Outlaw Quest Log (NAME).gba"
   (output size should be 16,777,240 bytes; build asserts that free space is 0xFF where it allocates)
2. STATE PAIRING. A RetroArch .state is an RZIP: 20-byte header (magic '#RZIPv', chunk size 0x20000 at
   offset 8, total size at 12), then chunks of [u32 compressed length][zlib data], each decompressing to
   up to 131072 bytes. The decompressed blob is 'RASTATE' + mGBA state. The ROM CRC32 (of the whole .gba file)
   is a u32 at decompressed offset 0x18. To re-pair: decompress, write zlib.crc32(rom) at 0x18, recompress
   in 131072-byte chunks. The mGBA-only state (what the harness loads) is raw[16:16+0x81040].
   The previous delivered state is a fine template (it contains the user's party/save data).
3. IPS: diff the new ROM against /home/claude/work/orig.gba, records of changed runs (merge gaps <= 2 bytes,
   max 0xFFFF per record, no record may start at 0x454F46 (the "EOF" value), all offsets < 0xFFFFFF).
   Apply it back to orig.gba and assert equality with the ROM before delivering.
4. Copy build.py and other changed source into out/source_tools/ (kept in sync each delivery).
5. Send .gba, .state, and the .ips with SendUserFile (display attach). Lead with what changed in
   plain words. State that it was verified in the emulator only.

6. KEY TECHNICAL NOTES
=====================================================================
ROM: FireRed 1.0 (BPRE), expanded to 16 MB. alloc(bytes, align) allocates from 0xA00000 upward.
Helpers in build.py: ptr(), text() (FR charset), thumb_fn() (keystone), r32/w32, setmove(), cp(table, size, dst, src).
c4(t) helper: 'ldr r4,=0x08000000+t+1; bl THUNK_R4' where t is a FILE offset (pass addr-0x08000000).
Existing trampolines live around 0x3af2a0..0x3af3a0; do not collide (mutagen wrappers are at 0x3af380+).

Species tables (index = species id): sprite tables front 0x2350ac, back 0x23654c (8 bytes: ptr, size, tag),
palette PAL / SHINY tables (8 bytes), sprite coords 0x2349cc and 0x235e6c, base stats 0x254784 (28 bytes),
names 0x245ee0 (11 bytes), species to national dex 0x251fee (u16, index species-1; the national to species
function searches this table linearly so a repurposed national number resolves to the new species),
dex entries 0x44e850 (36 bytes, indexed by NATIONAL number), evolution table 0x259754 (40 bytes = 5 x
{method u16, param u16, target u16, pad}; method 4 = level), TM compat 0x252bc8 (8 bytes), learnsets
LEARN=0x25d7b4 (u32 ptr per species; entries (level<<9)|move, 0xFFFF end), cries 0x48c914 and 0x48db44
(12 bytes, index species-1), party icons 0x3d37a0 (+ icon palette index 0x3d3e80, elevation 0x23a004).
Move data MOVE_DATA=0x250c04 (12 bytes), names MOVE_NAMES=0x247094 (13 bytes), descriptions MOVE_DESC=0x4886e8
(u32 ptr, index move-1). Dex category copy loop was patched to copy 12 chars with the 0xFF terminator.
Species limits: ids 252..276 are unused "?" slots (254..276 still free = 23 slots), 277..411 are real Hoenn data
(overwritable, 135 slots), 412 = Egg and the table edge. Past that needs relocating every species table.
Trainer data table at file 0x798790 (40 bytes: class, pic, name[12] at +4 ...). Object event templates are
0x18 bytes: local id +0, gfx +1, trainerType u16 +0xc, script ptr +0x10. The sight check requires the template
script to start with 0x5c (trainerbattle).
Script opcodes used: 0x26 specialvar, 0x21 compare_var_to_value, 0x06 goto_if, 0x0f loadword, 0x09 callstd,
0x02 end, 0x5c trainerbattle (type0 = 5c 00 id(2) 00 00 intro_ptr defeat_ptr), 0x39 warp, 0x44 additem.
Item struct 44 bytes at 0x3db028 (price at +16, desc ptr +20). Medicine flow hooks at 0x12533a, 0x12541e, 0x125516.
Evolution/summary note: when editing a test state, keep exp consistent with level and growth rate or the
summary screen's exp bar loop (code near 0x13aa2c) spins forever and looks like a hang.

Robbery/shoot mechanic: stage2/rob.c is C compiled to thumb. data.h is generated by prep.load() from
allmaps.txt giving g_ids[] / g_shoot[]. prep.py rules: plain scripts only, type 0 or 4 first trainerbattle,
only trainerbattle types 0/4/5.

8. TEST HARNESS
=====================================================================
tools/harness_ls: headless mGBA-based runner. Usage: harness_ls ROM SCRIPTFILE OUTPREFIX with env
LOADSTATE=<raw mGBA state file>. Script lines: "<frame> <hexkeys>" press, "<frame+4> 0" release,
"shot <frame>" (writes OUTPREFIX_%05d.ppm), "ram <frame> <hexaddr> <n>" (dump), "end <frame>".
Env PCS=<n> PCE=<m> samples the PC (a few false positives in BIOS/IRQ, e.g. 0x80008ac..b4 is a normal wait loop).
Key hex: A=1 B=2 Select=4 Start=8 Right=10 Left=20 Up=40 Down=80.
scratch_drivers/mt.py: go(name, keys, shots, endframe, rom, state, rams) runs it and builds a contact sheet PNG.
patchmon.py: patch(src_state, dst_state, slot, species=None, level=None) edits a party mon in an mGBA state
(handles XOR encryption and checksum). EWRAM is at state offset 0x21000, party at 0x02024284 (100 bytes/mon),
party count at 0x02024029.
Debug-only build env vars (NEVER ship): DEBUGWARP=group,num,x,y (the QUESTS menu entry warps there),
DEBUGITEMS, DEBUGCANDY (adds 30 Rare Candy), DEBUGTRAINER, DEBUGMUT, DEBUGMART, DEBUGBATTLE, DEBUGSE.
Start menu: cursor opens on the last used entry; QUESTS sits 3 above SAVE, BAG 1 above QUESTS, POKEMON 2 above QUESTS.
Typical party test: Start(8), Up, A (POKEMON), A (select), A (SUMMARY), Right to change pages.
Bag opens on the Key Items pocket; press Left once for Items, Down many times to reach the end.
